## RuntimeTrace v0.1.0: first release

**A runtime cross-layer consistency checker for Linux, powered by eBPF.** PhantomTrace asks whether an offline NTFS disk agrees with itself. RuntimeTrace asks the same question on a live system: does the kernel's own ground truth about what's running agree with what `ps`, `lsmod` and friends report? Process-hiding rootkits and some anti-forensic techniques work by making exactly one of those views lie.

```bash
sudo apt install python3-bpfcc                       # the real eBPF toolkit (a system package, not pip)
pipx install --system-site-packages runtime-trace
runtime-trace                                        # instant: no root needed
sudo runtime-trace --watch 30                        # also watches live process execution
```

### What it checks

- **Hidden processes:** a pid the kernel scheduler ran, missing from this computer's own `/proc` (needs `--watch`, root).
- **Fileless execution:** a program run straight from a memfd or an anonymous file descriptor, never from a file on disk (needs `--watch`, root).
- **Hidden kernel modules:** `/proc/modules` and `/sys/module` disagree about what's loaded.
- **`/etc/ld.so.preload`** populated (loaded into every new process).
- **Per-process `LD_PRELOAD`** pointing outside the standard system library paths.
- **Deleted-but-running binaries** (`/proc/<pid>/exe` marked `(deleted)`).

No bundled sample data: every check runs against your own real system.

### Honest about the gaps

- Android is scoped, not implemented: it needs root, a GKI kernel, and a cross-compiled native loader I could not build or test without a real rooted device. The README explains exactly what's missing.
- `ppid` isn't populated on live exec events yet.
- Tested so far on a stock Ubuntu kernel with BTF. Please report anything that behaves differently on your distro or kernel, especially false positives.

### Two real false positives, found and fixed before release

Building this on a real, ordinary development machine immediately surfaced two problems worth being upfront about: comparing `/proc/modules` against *every* `/sys/module` entry flagged over a hundred "hidden modules" that were simply compiled into the kernel and never loaded; and Firefox's and Discord's own snap sandboxing routinely sets `LD_PRELOAD` to their own compatibility shims, which is normal, not injection. Both are fixed, and the README explains why, the same way PhantomTrace's README documents its own known limitations.
